# Thermonuclear Review - Realtime Transcription Streaming

Date: 2026-05-28
Scope: Phase 1 relay Realtime transcription contract, Phase 2 Swift store-owned draft reconciliation, Phase 3 typed Swift relay-client integration, Phase 4 live capture/audio-forwarding/tap-control physical pass, Phase 5 cutover cleanup, and standalone relay-to-OpenAI proof
Verdict: Phase 5 cutover cleanup and follow-up structural cleanup passed programmatic/real-relay proof, and the basic physical iPhone 14 Realtime audio path passed by user manual test after the empty-transcript relay fix. Detailed manual checklist evidence for typed-prefix preservation, explicit Send/no auto-submit, cancel/interruption recovery, and accessibility remains pending.

## Findings Reviewed And Repaired

- Plaintext OpenAI Realtime endpoint risk: production relay config previously allowed `ws://`, which could send `OPENAI_API_KEY` over plaintext if misconfigured. Fixed by requiring `wss:` in `scripts/dock-relay-realtime-transcription.mjs`; tests now use an injected WebSocket factory instead of weakening production validation.
- Pending queue bound gap: append validation previously checked only current `bufferedAmount`. Fixed by rejecting when current pending bytes plus decoded chunk bytes exceeds `realtimeTranscriptionMaxPendingBytes`.
- Shutdown cleanup gap: relay shutdown previously did not explicitly close active downstream phone sockets. Fixed by tracking downstream sockets in `scripts/dock-relay.mjs`, closing/terminating them during `relay.close()`, and proving active Realtime upstream cleanup.
- Realtime transcription URL mismatch: endpoint URLs with an existing `model` query can open the wrong OpenAI Realtime session type. Fixed by forcing `intent=transcription`, stripping any `model` query from the URL, and keeping `gpt-realtime-whisper` only in `session.audio.input.transcription.model`.
- Malformed upstream event gap: malformed delta/completed events could be ignored or treated as successful completion. Fixed by failing the session with sanitized `invalid_upstream_event`.
- Safety identifier override gap: phone-supplied `OpenAI-Safety-Identifier` variants were not rejected. Fixed by adding safety identifier names to the forbidden provider field list and tests.
- Hidden one-shot fallback risk: an interim Swift adapter could have made `ThreadDetailStore` look like it was using Realtime while silently returning to one-shot `audio/transcribe`. Fixed by making the Phase 2 default voice path fail visibly with `Realtime transcription is not connected yet.` until Phase 3 wires the real relay-backed streaming client.
- Draft corruption risk: streaming deltas could duplicate text or overwrite typed prefix text. Fixed by using cumulative `partialText` to replace only the active provisional segment and preserving user text outside that segment.
- Edit race risk: user typing and streaming transcript events could both mutate `composer.draft`. Fixed by locking `updateDraft(_:)` while voice is starting, streaming, or finalizing.
- Stop-reason drift risk: explicit cancel, close, failure, and app background needed different draft outcomes. Fixed by removing the provisional segment on explicit cancel/close, freezing visible partial text on recoverable failure/background, and preserving the original draft when failure happens before any partial text.
- Send race risk: voice partial/final events could lead to accidental turn submission. Fixed by keeping `composer.canSend` false while voice is active and preserving manual Send only.
- Untyped Swift relay-client risk: production voice could keep constructing raw method strings or reuse the thread-detail session. Fixed by adding typed Realtime transcription DTOs and `AppServerClient` wrappers, plus `RelayRealtimeTranscriptionClient` with its own app-to-relay connection.
- Wrong-session event risk: relay notifications for another session could mutate the active composer. Fixed by filtering notification `sessionId` and testing ignored out-of-session delta events.
- Hanging finalization risk: commit could return but no completed/failed event could arrive. Fixed by adding a client-side commit timeout that emits a safe failure and closes the voice connection.
- Cleanup risk: voice WebSocket sessions could survive completion/failure/cancel. Fixed by closing the separate voice `AppServerClient` on completed, failed, timed out, and canceled paths.
- Missing microphone audio upload risk: `ThreadDetailStore` could start and commit a realtime session without sending any microphone audio. Fixed by adding live capture ownership to the store and forwarding each `VoiceAudioChunk` to `RealtimeTranscriptionSession.appendAudio(...)` before commit.
- Mid-gesture release risk: the mic button could disable itself after `.starting`, potentially losing the drag release callback. Fixed by keeping the mic control enabled during voice state transitions while store guards prevent duplicate starts.
- Late-release timing gap: releasing before `startSession()` completed was untested. Fixed with a delayed-start test that marks `.finalizing`, then commits after the session and capture path become available.
- Client chunk-boundary gap: the Swift client relied on relay-side chunk validation only. Fixed by rejecting empty and oversized chunks before sending `audio/transcription/append`, and by validating accepted append sequence numbers.
- Tap accessibility gap: the composer had hold-only dictation controls. Fixed by adding a separate tap-to-start/tap-to-stop control, `ComposerVoiceInteractionMode`, `ThreadDetailStore.toggleTapVoiceCapture()`, and presentation tests for labels, hints, disabled states, status text, and icons.
- Hold/tap cross-finalization gap: a stale hold-release callback could finalize an active tap session. Fixed by making `finishVoiceCapture(interactionMode:)` ignore mismatched interaction modes.
- Capture route/interruption cleanup gap: live capture did not react to audio session interruptions or relevant route changes. Fixed by observing `AVAudioSession.interruptionNotification` and route changes, then finishing capture cleanup through the main-actor session path.
- iOS actor-isolation build gap: route/interruption cleanup initially called capture cleanup from nonisolated contexts and failed the iOS simulator build. Fixed by scheduling notification cleanup on `MainActor` and wrapping NotificationCenter observer tokens so Swift 6 accepts deinit cleanup.
- Legacy one-shot side-door risk: Phase 5 could have left direct Swift OpenAI upload, one-shot relay upload, typed app DTO/client helpers, or old relay helper exports around as a hidden fallback. Fixed by deleting `OpenAITranscriptionClient`, `RelayTranscriptionClient`, `TranscriptionServicing`, `AudioTranscriptionDTO.swift`, `AppServerClient.audioTranscribe(...)`, `AppServerMethods.audioTranscribe`, `scripts/dock-relay-transcription.mjs`, old relay helper exports, and old one-shot tests.
- Legacy relay-call bypass risk: deleting typed Swift APIs alone would not stop a raw JSON-RPC caller from invoking `audio/transcribe`. Fixed by removing relay handling and proving raw `audio/transcribe` returns `-32601`.
- Old file-recorder risk: `VoiceCaptureController`/`VoiceCaptureControlling` could have kept m4a capture available for production reuse. Fixed by deleting the AVAudioRecorder-based controller, the `notRecording` file-recorder error, and the dead m4a fake capture helper.
- Service config drift risk: generated service env and LaunchAgent args could have kept `CODEX_DOCK_OPENAI_TRANSCRIPTION_MODEL` or `--openai-transcription-model`. Fixed by removing the old variable/arg, adding Realtime delay config, and checking generated `.codex-dock/service.env` for old config absence.
- Xcode stale-file risk: deleting a Swift file without regenerating XcodeGen could leave stale project references. Fixed by regenerating with `rtk xcodegen generate --spec project.yml`; Xcode build removed stale `AudioTranscriptionDTO` objects and passed.
- Proof-harness false-negative risk: the first restarted-relay proof failed because the harness split PCM16 into odd-byte chunks. A direct OpenAI probe showed `invalid_value` for invalid PCM bytes; rerunning through the relay with even chunk boundaries passed. This was a proof harness bug, not a relay/app defect.
- Physical automation churn risk: repeated physical Mobile MCP attempts would waste time because WebDriverAgent is not running. Fixed operationally by stopping physical Mobile MCP usage and leaving final physical iPhone 14 proof to Amir's manual test.
- Listening-state color risk: active voice UI used red, making a non-error listening state look like a failure. Fixed by making the hold/tap mic tint and streaming status blue in `CodexDock/Features/Session/ComposerView.swift`; red remains only for real error labels.
- `ThreadDetailStore` size/ownership risk: voice/composer state and voice-capture orchestration had made the core detail store too large after the Realtime work. Fixed by moving the voice/composer state machine into `CodexDock/State/ThreadDetailStore+Voice.swift`; current line counts are `890` for the core store and `556` for the voice extension.
- Relay server size/ownership risk: thread-list/read/archive aggregation had made `scripts/dock-relay.mjs` too large after the Realtime and live-row work. Fixed by extracting thread data helpers into `scripts/dock-relay-thread-data.mjs`; current line counts are `649` for the relay server and `657` for the thread-data helper.

## Acceptance Boundary

The fake/mock tests still do not count as acceptance proof because they use fake/mock upstreams, fake Swift streaming sessions, fake capture chunks, or scripted relay notifications. Standalone real relay-to-OpenAI proof, Phase 5 cutover cleanup, and basic physical iPhone 14 audio proof are now satisfied, but full voice closeout still requires recorded evidence for:

- successful held-mic proof and successful tap-mode proof;
- typed-prefix survival, editable final draft, and manual Send/no auto-submit;
- cancel/interruption recoverability;
- accessibility proof for VoiceOver labels/hints, hit targets, and large Dynamic Type layout.
