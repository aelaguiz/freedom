## Agreements (locked)

- **Reuse, don't duplicate.** The judge/orchestrator imports `dock-relay-sync-audit.mjs`; that script stays the single relay/client-route truth. No second relay-truth collector.
- **Real path only.** Launch with `CODEX_DOCK_HOSTS=…:4510`, never `CODEX_DOCK_UI_DOCK_STREAM_SCENARIO` (the scripted mock gate at `CodexDockBootstrapView.swift:121`), never raw `:4500` (`validateAppFacingRelayEndpoint`). Makefile-owned target, not raw `xcodebuild`.
- **Accessibility tree is the proof surface** — Dock root/row, session root/header/message-list, message/request ids — and it is literally what SwiftUI drew.
- **Lag = rendered UI treated as a stream consumer**, scored with the existing `evaluateStreamConvergenceLag`/`applyStreamLagBudget` against `t_relay_seen`; eventual match never rescues a slow screen.
- **Single-host canonical**, multi-host as the host-isolation extension.

## Disagreements / corrections (three, all decidable by repo evidence)

1. **Orchestration must be concurrent, not sequential.** Model B writes "runs the relay audit; runs the UI proof; merges." If read literally that's sequential and the time-join has nothing to join — the relay soak recorder and the UI sampler must overlap in wall-clock time. The orchestrator must run the relay `soak` recorder (in-process via import or a child process) **concurrently** with the `xcodebuild` UI test, same duration, then judge. This is the one real defect in B's structure.

2. **Passive real-home is necessary but not sufficient for a completion-grade lag proof.** I am correcting my own round-1 "Tier A suffices" here. The relay reconciles every 30 s (`dock-relay-constants.mjs:35`, cited plan:193) and a quiet real home may emit no content change during a run, so a passive pass can be **vacuous** — it never exercises the lag-failure path and can't produce deterministic missing/stale/order/archive transitions. Forced `dock/resync` and detail-opens exercise paths but are read-only snapshot replacements, not content-change lag. Deterministic lag needs a **content change**, and the only mutation-safe way is an **isolated `CODEX_HOME` actuator** (create thread / add turn / archive-unarchive) — which is the plan's **Controlled Scenario Runner (Phase 4)** owner path, currently a stub (`buildScenarioReport` emits `scenario_actuators_not_implemented`). So the simulator leg's deterministic completion **depends on a thin Phase-4 actuator**; it must not rebuild it and must not archive/mutate the user's real threads. Passive real-home stays as a weaker supplementary regression mode. Neither of our round-1 drafts weighted this correctly.

3. **Fingerprint scope must exclude client-derived fields.** I adopt Model B's sanitized-fingerprint instrumentation (it's the redaction-safe way to catch "stale/wrong displayed text," which my structural-only round-1 missed) — but Model B's "title/summary/body-like fields" is too broad. The client **derives** preview from "true messages" and drops tool/reasoning noise (the `messageNoise` scenario; `ScriptedDockStreamClient`/`DockSharedViews`), so the displayed preview is intentionally ≠ the relay `preview`/`latestSummary` field. Fingerprinting derived preview would false-fail. Scope fingerprints to **1:1 fields only**: Dock row **title**, detail event **title/body** — not preview/summary.

## Simplifications I recommend

- **Row-set scope = watched/visible every sample + full-list sweep only at checkpoints** (adopting B's vote, answering focus Q2). Per sample: read the materialized rows (no scroll) + root `rows=N` for cheap gross-completeness and per-row/lag checks. Full scroll sweeps (missing/extra/duplicate/order vs relay full set) run only at start/end/stable checkpoints, and are **excluded from lag timing** because scrolling self-perturbs the UI. Full-list-every-sample is impossible at a ≤500 ms cadence and is evidenced as expensive by the existing `scrollUntilElementExists` multi-swipe helpers.
- **Drop rendered-seq instrumentation for v1.** Time-window join on the shared Mac clock (sub-100 ms skew; sampling ≤ budget/4) is adequate for a 2 s budget. Relay `seq`/`epoch` label the relay-truth timeline for reporting (B's keys), but the UI need not emit seq. Keep a clock-skew guard. Treat rendered-seq as a deferred exactness upgrade only if the time join proves flaky.
- **No app-emitted render timestamps** (focus Q4). Interval sampling baseline; for deterministic scenario events use the existing `waitForStringValue` early-exit poll for precise `t_ui_seen`. That's the whole timing story.
- **One judge file, importing the canonical comparators** (focus Q1) — `compareDockStates`, `evaluateStreamConvergenceLag`, `cardID`, `normalizeForComparison`, `textFingerprint`, report schema — emitting a `renderedUI` plane. Not a `--ui-samples` mode bolted into the 2,044-line audit script.

## Repo evidence that decides the disagreements

- **Sibling-imports-canonical (Q1):** `dock-relay-sync-audit.mjs` already imports `buildReport`/`parseArgs` from `dock-relay-state-parity.mjs` and re-exports its own comparators (`export { … }`, file end). The plan mandates this exact pattern: "exports collectors and comparators for the new audit script… Do not create a second definition." Decisive for sibling.
- **Lazy-list scope (Q2):** existing UI tests scroll via bounded `maxSwipes` loops with RunLoop settles (`CodexDockAutomationSmokeTests.swift`), and SwiftUI only materializes on-screen cells; `dockScreenValue` (`DockView.swift:786`) exposes `rows=N` total without materializing rows. Supports watched + checkpoint-sweep + cheap count-check.
- **Passive-not-sufficient (Q3):** 30 s reconcile interval (plan:193); scenario actuators are a stub (`buildScenarioReport`); `thread/archive`/`thread/unarchive` are real appCritical routes (`ObservabilityContract.swift:57–58`) but mutate real user data, so deterministic change belongs in an isolated-home actuator, not against the real home.
- **Fingerprint scoping (Q3/Q5):** the client derives preview from true messages and suppresses tool/reasoning text (`messageNoise` scenario in `ScriptedDockStreamClient`/`ThreadMessageListView`), so preview is not 1:1 with relay fields; title and event body are. The audit already fingerprints text via `textFingerprint` + `TEXT_FIELD_RE` (`dock-relay-sync-audit.mjs:426`), so client/relay can share one fingerprint function.
- **App-side fingerprint is the redaction-safe mechanism (Q5):** having the *app* emit `sha256→16hex` over the bound source string keeps raw transcript/body text out of the harness process entirely — the cleanest way to honor "do not log transcript/raw bodies." Render snapshot already carries `hostStates` + freshness (the `Offline` label assertion proves it), so stale/offline is provable with no new instrumentation; only the two 1:1 fingerprints are new.

## Revised proposal (converged)

- **Sampler** (`CodexDockUITests`, real path): per-interval read of Dock root (`rows/pinned/lens/state` + freshness) and materialized rows (`host/thread/status/origin/label/pin` + **title fingerprint**); checkpoint full-sweep for set/order/dup/missing; detail mode reads `host/thread/live/events/status/filter` + event-id set + **event title/body fingerprint** + request `card/kind/status`. Emit sanitized JSONL via `XCTAttachment`. Wall-clock + monotonic stamps. No raw text.
- **Two new app fingerprints only:** row title, detail event title/body, via shared `textFingerprint`, gated behind a bring-up parity test (client fp == relay fp for a known card) before they can fail CI.
- **Relay-truth recorder:** existing audit in `soak` + small `--stream-event-log` for fine `t_relay_seen`, run **concurrently** with the UI test.
- **Judge** (`scripts/dock-relay-sim-ui-audit.mjs`): imports canonical comparators; time-window join + `(logicalHostID, threadID)` key (`DockHostIdentityResolver`); relay `seq/epoch` label the timeline; lag via `evaluateStreamConvergenceLag`; `renderedUI` plane + `U-xx` invariants + `dock_ui_*`/`detail_ui_*` codes.
- **Completion modes:** **scenario mode against an isolated `CODEX_HOME`** (depends on the thin Phase-4 actuator) is the completion-grade lag proof; **passive real-home** is the supplementary regression mode. Duration ≥ ~3× reconcile (≥ 90 s) regardless.
- **Makefile** `sim-sync-audit SIM='iPhone 17'` orchestrates concurrently; artifacts under `/tmp/codex-client/sim-ui-audit/`; `--fail-on-diff`; run twice (gate item 14).
