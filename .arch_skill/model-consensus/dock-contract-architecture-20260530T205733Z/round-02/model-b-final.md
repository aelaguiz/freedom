**Agreements**

- The current bug is contract drift: relay has `summary`/`updatedAt`, Swift sorts/renders from missing `messageSummary`/`messageUpdatedAt`.
- The bounded stream model stays: `dock/subscribe`, `dock/update`, `dock/resync`, windows, byte caps, deltas, and lazy detail loading.

**Disagreements And Resolution**
- `DockThreadCard` vs `DockRow`: adopt Claude’s `DockRow`. “Card” is too UI-specific and risks confusion with request cards; this contract is the row/list/detail spine.
- “Client does not project at all”: too broad literally. Correct version: client does not re-derive semantic truth. It may filter/group/search/present using canonical `DockRow` fields.
- `orderKey`: not dense rank, not public tuple, not display timestamp. Use a required opaque lexicographic string token, generated only by the relay. Also carry `activityAt` separately for display.
- Schema source: do the minimal durable thing, not a giant framework. One small repo-local schema for `DockRow` and stream envelopes, with generated Swift DTOs and Node validators/builders.

**Simplified Architecture**
`DockRow` is the app-facing product model. The relay projects raw Codex `Thread` plus relay state into `DockRow`; Swift decodes it and renders it.

Core fields:
`id`, `logicalHostID`, `threadID`, `backendSessionID`, `orderKey`, `activityAt`, `title`, `summary`, `status`, `source`, `repo`, `workingDirectory`, `branch`, `archiveState`, `freshness`, `completeness`.

`orderKey` contract:
- Swift compares it lexicographically and treats it as opaque.
- Relay builds it from versioned structured inputs, for example recency descending plus upstream-compatible UUID tie-break plus logical host tie-break.
- `activityAt` is the human timestamp. It is not the ordering authority.
- When upstream later exposes millisecond order metadata, only the relay’s `orderKey` builder changes.
