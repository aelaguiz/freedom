# Round‑01 — Opus 4.8 consensus position: Codex Dock unified live‑update architecture + ongoing proof

## Headline (and where I differ from GPT‑5.5)

GPT‑5.5's pass is correct and I converge with ~90% of it. But it misframes the testing half. It proposes the five proof tiers **as if they need building** ("`sync-audit.mjs` *must* compare long‑lived stream vs fresh snapshots…"). They already exist and are proven on real local services (per `..._IMPLEMENTATION_LOG`). **The disease is not missing real‑world tests — it is that the real‑world proof is opt‑in, default‑off, unscheduled, and ungated, so drift accrues between runs nobody triggers.** The clinching evidence is that the methodology docs themselves have rotted: the RUNBOOK and TEST_PLAN both tell you to run `dock-relay-sync-audit.mjs --exhaustive` (the flag does not exist in `parseArgs` — it throws) and `scripts/dock-relay-state-parity.mjs` (deleted). If anyone ran the documented loop, those breakages would surface instantly. That is *exactly* why the user is "chasing bug after bug": the proof that would catch them is shelfware.

So the canonical answer is **enforcement + cadence + drift gates on the harness that already exists**, not a new framework. That keeps us at the "minimal new abstractions" bar.

## The architecture, compressed to 3 generating principles

The reference doc has 11 rules and 11 bugs; GPT‑5.5 has 7 rules. All of them collapse into three invariants, which is the "most elegant" framing the user asked for:

**P1 — One owner per fact; no second oracle.** Card truth = relay `dock/*`/`archive/*` only. Detail history = `thread/read includeTurns:false` + fully paged `thread/turns/list`. Detail liveness = forwarded `thread/resume` session. Recency = relay `orderKey` (client never re‑derives from timestamps/text/pins). Freshness/completeness = relay‑computed, per card. Local metadata/pins/aliases **decorate**, never create/reorder/freshen/delete. Route health ≠ data freshness. *(Subsumes reference rules 1–9,11; GPT‑5.5 rules 1–5. Kills drift‑by‑duplication.)*

**P2 — Liveness must be positively and continuously re‑proven; a connected socket is never proof.** Every relay‑owned stateful stream/session carries an identity (`epoch`/`generation`/`seq`). Whenever the relay's binding for that stream changes identity — downstream socket reconnect, subscription dropped on close, **or the relay's *upstream* `thread/resume` re‑resume** — the missing state MUST be rebuilt (resubscribe for cards, rehydrate for detail), and the relay MUST make that identity change observable downstream. *Bug #1 (Dock reconnect doesn't resubscribe) and bug #2 (detail upstream recovery is invisible) are the same bug.* This is the load‑bearing principle and the one the current code violates in two places.

**P3 — Proof = over‑time convergence of real app‑server → relay → client → rendered UI, enforced on a cadence, or it does not count.** Static snapshots/fixtures only prove the final merge step. Canonical proof is: long‑lived real stream vs fresh real snapshot sampled over a duration with a lag budget; controlled server‑state transitions; the literal simulator display sampled over time; physical phone for completion — and it must be *mandatory and scheduled*, because an opt‑in proof nobody runs is how drift returns.

## Proposed architecture (lean, end‑to‑end)

Adopt GPT‑5.5's 7 rules verbatim as the concrete expression of P1+P2, with three corrections from my evidence:

1–6. (unchanged from GPT‑5.5) Phone↔relay `:4510` only; card truth from `dock/*`/`archive/*`; relay owns freshness/order/human‑filter/SQLite; Swift renders `orderKey`, metadata decorates; detail follows read→paged‑turns→resume; no silent reconnects for stateful paths — identity change forces rebuild.

7. **Detail upstream recovery → close the downstream phone socket** (this resolves GPT‑5.5's Decision 1 — see below).

**Correction A (freshness must fail closed on live failure).** Today a live‑endpoint outage does **not** degrade Dock `complete`/freshness — `collectLiveRows` counts `failedEndpoints` but `refreshLiveLeases` discards it, and the only path that would mark the scope stale (`ingestLiveDisconnect`/`markScopeStale("live-leases")`) has **no caller** (verified). So history completeness hides a live outage. Canonical rule: any live‑scope probe failure must mark the reconcile scope incomplete → `freshness:"stale"`, and the client must render stale, not silently‑fresh.

**Correction B (snapshot recency guard).** Swift's `applySnapshot` overwrites state with no recency check; a delayed/older `dock/subscribe`/`dock/resync` snapshot can move the UI *backward*. The DTO already carries `stateGeneration`/`seq` but the client ignores them (dead field). Canonical rule: relay stamps a monotonic generation on every snapshot; client rejects a snapshot whose generation < current. One field, already on the wire, currently unused.

**Correction C (relay→Archive reconcile).** `thread/archive`/`unarchive` ingestion calls `reconcileDock` only; `reconcileArchive` is reachable solely from `archive/subscribe`/`archive/resync` (verified). Archive mutation must explicitly reconcile the Archive view so `archive/update` subscribers converge. (Also: host freshness is global across scopes, so Dock/Archive currently stale each other — split freshness per scope.)

## Resolving GPT‑5.5's three challenges (with repo evidence)

**Decision 1 — detail upstream recovery: I CONVERGE on "close downstream," with stronger reasoning + a sanctioned escape hatch.** Closing the phone socket reuses Swift's **already‑tested** rehydrate path (`reconnecting → read → drain → resume → merge`) with **zero** new protocol/handler/test surface — maximally drift‑resistant, satisfies P2 directly. I reject the "leave it invisible" status quo and reject silently adding a new notification. *But* the doc must honestly record the cost (full re‑drain of all turn pages on what may be a sub‑second relay blip; drops in‑flight composer/transcription state) and name the one principled alternative — a `generation`‑ and `threadId`‑stamped `detail/resync` downstream notification, symmetric with the existing `dock/resync` — as **rejected‑for‑now, not a side door**. If a future perf need forces it, it enters via the allow‑list + Swift DTO + tests + doc in one change, and must be `threadId`‑stamped to survive Swift's "drop notifications missing `threadId`" guard. Net: close‑downstream now; symmetric resync is the only sanctioned future evolution.

**Decision 2 — full detail history: CONVERGE and STRENGTHEN; the open question is resolved.** The enum is real and in‑repo: `TurnItemsView = { notLoaded, summary, full }`, default `summary`, `full` = "every reconstructed `ThreadItem`" (`CODEX_APP_SERVER_THREAD_MESSAGE_TURN_DATA_REFERENCE`, `thread_data.rs:174/184`). So the contract value is `itemsView:"full"` — no longer a guess. **Scoping correction GPT‑5.5 missed:** `itemsView:"full"` belongs **only** to the Thread Detail rendering path; the relay's card‑ordering activity‑proof calls to `thread/turns/list` must **not** request `full` (they need turn timestamps, not bodies — forcing full there is wasteful and conflates two concerns). Rule: pin `itemsView:"full"` for detail turn requests (Swift `ThreadTurnsListParams` field or relay injection on the detail route), keep it **off** the relay proof path, and assert the actual outbound params in tests. Because default is `summary`, a green `thread/turns/list` proves pagination, not completeness — the detail‑completeness invariant must assert full item kinds (command/tool/file‑change) are requested **and rendered**.

**Decision 3 — heartbeat: I take a firmer position than "decide" — MAKE IT REAL.** Today heartbeat is dead contract claimed in three places (Swift accepts it + has stale‑heartbeat tests; JSON schema allows it; README says `dock/update` carries heartbeats) but the relay never emits one — a drift the user's own README embodies. Per P2, liveness must be *positively* proven, and a periodic relay→phone `kind:"heartbeat"` carrying `{epoch, seq, freshness, lastSyncAt}` (no row change) **is** that proof: it lets the client detect a connected‑but‑stuck/unsubscribed stream (bug #1) and surface stale UI when heartbeats stop or freshness degrades. The alternative — delete heartbeat everywhere — forces a client‑side "no update in N intervals → reopen" watchdog, which is a client heartbeat reinvented with less information. So **heartbeat‑real is strictly leaner than remove‑and‑reinvent.** Recommendation: make it real; if the team insists on minimum surface, removal is acceptable *only if* paired with the client watchdog (otherwise the architecture stays reliant on the false socket‑liveness signal we're eliminating).

## Ongoing testing methodology (the smallest delta on what exists)

Keep the six tiers that already exist; make them mandatory, default‑on, scheduled, drift‑gated, and trended.

- **Tier A — Contract/drift gates (CI‑safe, fast).** Existing: `contract:check` (schema const, Ajv fixtures, generated‑DTO staleness, forbidden legacy keys, freshness invariants). **Add four cheap gates** for the seams that actually bite: (1) relay dispatch‑switch method set == `ROUTE_CONFIGS` keys (today `ensureRoute` silently absorbs unregistered routes); (2) `schemaVersion=2` cross‑language assertion across JSON‑schema const, Swift `streamSchemaVersion`, and the relay's bare `schemaVersion: 2` literals (three independent hardcodes today); (3) **doc‑command executability gate** — lint the RUNBOOK/TEST_PLAN command blocks against the real arg parser and `make -n` (this would have caught `--exhaustive` and the deleted parity script); (4) heartbeat‑contract gate — relay emits iff Swift/schema/README claim it.
- **Tier B — Swift unit (fake stream).** Keep; add the missing strictness the audit exposed: missing‑params `dock/update` = corruption (not silent skip), older snapshot can't clobber newer (generation guard), duplicate card ids rejected before dictionary build (current snapshot path *traps*), non‑human upsert of an existing human card forces delete/resync.
- **Tier C — Relay `node --test`.** Keep (card‑contract, observability side‑door negatives, transcription, comparator units, fixture/matrix arg tests).
- **Tier D — Real‑relay client‑path soak** (`dock-relay-sync-audit.mjs`): long‑lived stream vs fresh snapshot, forced `dock/resync`, detail probe, **lag budget** (`--max-stream-lag-ms 2000`), soak (time‑based), scenario matrix (16 controlled transitions on real relay routes w/ controlled upstream fixtures). Tighten existing scenario assertions to **fail** on the known bugs (archive‑toggle must prove `archive/update`; live‑lease‑expiry must degrade freshness; detail‑reconnect must prove upstream‑recovery → downstream rebuild).
- **Tier E — Displayed‑UI over time** (real app + real relay; `CodexDockDisplayedSyncProofTests` → `dock-relay-simulator-ui-sync-proof.mjs` judge → controlled fixture → matrix; `sim-ui-controlled-matrix-proof`, 2 passes, `MAX_UI_LAG_MS=2000`, ≥2 consecutive passing samples, per‑transition coverage, dup‑report rejection).
- **Tier F — Physical phone** for completion (`iphone-17-pro`, `device-config-verify`).

**The five enforcement changes that are the actual fix (this is what's new):**
1. **Umbrella + CI + pre‑push:** one aggregate target (e.g. `make verify`) running the CI‑safe subset (Tiers A+C + `node --check` + new gates) on every change; a CI workflow (none exists today — no `.github/`, no hooks, no aggregate `make test`).
2. **Flip over‑time proof from opt‑in to required for update‑path changes.** Today `DisplayedSyncProofTests` `XCTSkip`s unless `/tmp/codex-client/codex-dock-sim-ui-sync-config.json` exists+unexpired, so plain `app-test` proves structure, not freshness. Gate update‑path PRs (path filter on relay/stream/detail/contract files) on a passing `sim-ui-controlled-matrix-proof`.
3. **Scheduled soak + matrix** (nightly/cron) so "over time" is a real time series, not a single pass.
4. **Drift gates** (Tier A additions above) as the standing guard against protocol/data/doc drift.
5. **Retention + trend:** persist each scheduled run's JSON under a retained tree; trend `maxObservedUiLagMs`/failures so regressions are visible across runs (the "ongoing" proof is a trend, not a snapshot).
